# Темы тайтлов: свой UI/UX/VFX для каждого тайтла

Каждый тайтл оформляется не перекраской, а собственным дизайном: своя раскладка серий, свой способ отмечать, свой опросник и своя «печать» оценки, свои эффекты и сгенерированные ассеты. Движок тот же, что в Completionist List (`D:\ComplitionistList`), — его темы годятся как образцы приёмов (но не для копирования композиции).

```
themes/<id>/
  theme.css     — стили баннера на главной и страницы тайтла (грузится сразу, если theme.css: true)
  theme.js      — модуль: строит баннер, сцену наведения, заставку и всю страницу (theme.js: true)
  assets.json   — промпты сгенерированных ассетов (чтобы можно было перегенерировать)
  assets/*.webp — сами ассеты
```

Флаги `css` и `js` ставятся в `theme` тайтла в `data/titles.json`. Цвета, шрифты, частицы и текстуры из `theme` продолжают работать — модуль строится поверх них.

## theme.css

- Селекторы **только** с префиксом тайтла: `.tbanner[data-title="<id>"] …` (баннер на главной), `.stage-layer[data-title="<id>"] …` (фон главной при наведении) и `html[data-title="<id>"] …` (страница). Классы, которые добавляет модуль, — с коротким префиксом тайтла (`sh-`, `fr-`, `bk-`…), чтобы не пересечься с другими.
- Пути к ассетам относительные: `url(assets/frame.webp)`.
- **Общий каркас сайта не перекрашивать.** Всё, что видно про тайтл, тема строит сама в `theme.js` (`banner`, `stage`, `page`, `cover`) и стилизует своими классами. Общая разметка — только запасной вид для тайтла без модуля.
- **Баннер на главной** — `banner(b)` строит его содержимое; сама ссылка `<a class="tbanner <status> themed-card" data-title="<id>">` остаётся (на ней наведение, фокус и вход в тайтл), её рамку, фон и эффект наведения тема задаёт сама (у `.tbanner` свободны `::before` и `::after`). **Форма — любая**: прямоугольник не обязателен (и нежелателен — пользователь: «свобода дизайна должна быть во всём»). Тема сама задаёт высоту и силуэт (маски, `clip-path`, прозрачные края) и может выступать за свою полосу: крылья, пламя, рваный край, герой поверх рамки — список баннеры не обрезает (`.cat-inner` режет содержимое только на время сворачивания категории), а баннер под курсором движок поднимает над соседями (`z-index`). Ограничения — только здравые: в покое не закрывать название и оценку соседей, не давать горизонтальной прокрутки страницы, оставить понятную область нажатия. Запасной вид без модуля: `.tb-media`, `.tb-body`, `.tb-main`, `.tb-title`, `.tb-progress`.
- **Выбранный баннер**: по клику движок ставит баннеру класс `.picked` — пока главная растворяется, мышь с баннера «уходит», и `:hover` пропадает. Выделение темы писать как `:is(:hover, .picked)` (и отдельно `:focus-visible`), чтобы оно держалось до заставки.
- **Сцена** (`#stage`): при наведении на баннер за списком включается `.stage-layer[data-title="<id>"]`. Что в нём происходит, решает тема в `stage(s)` — своя задумка тайтла, только на CSS-анимациях (идут, пока у слоя класс `.on`), а не кусок страницы тайтла. Где баннер, на который навели, движок пишет в переменные слоя: `--bcx`, `--bcy` — центр, `--bw`, `--bh` — размер (px, в координатах окна; обновляются при прокрутке). Без модуля — общий `.stage-hero` с артом.

## theme.js

```js
TitleThemes.register("<id>", {
  banner(b) { b.el.innerHTML = `…`; },          // главная: свой баннер (b.el — <a class="tbanner">)
  stage(s) { s.el.innerHTML = `…`; },           // главная: что происходит при наведении на баннер
  cover(t) { /* начало заставки на главной */ }, // см. ниже
  page(ctx) {
    ctx.root.innerHTML = `…`;                   // вся страница тайтла — своя
    ctx.onChange(() => { /* отметка изменилась — перерисовать серии, прогресс, оценку */ });
    return () => { /* необязательная своя уборка */ };
  },
});
```

`b` и `s` (главная): `el`, `item` (запись из titles.json), `progress` (см. ниже), `score` (оценка 0–10 или `null`), `assets`, `art.hero(attrs)` / `art.logo(attrs)` / `art.cover(attrs)` — теги `<img>` с запасными адресами (`logo()` — пустая строка, если логотипа нет), `reducedMotion`, `finePointer`, `esc`, `safeUrl`, `plural`, `unitWord`, `fmtScore`. Модули грузятся на главной сразу; пока модуль не загрузился, баннер скрыт (`.module-pending`). После каждой отметки список перерисовывается, и `banner(b)` вызывается заново со свежим прогрессом.

`progress`: `{ parts: [{ id, title, unit, count, watched }], watched, total, status, last, next, score }`. `status` — `planned` (ничего не отмечено), `watching` или `completed` (отмечено всё и тайтл не `ongoing`). `last` — где остановился: `{ part, n }` или `null`; `next` — что отмечать следующим: `{ part, n }` или `null`.

`ctx` (страница):

| Поле | Что это |
|---|---|
| `item` | запись тайтла из titles.json; свои картинки темы — в `item.images` (`{ имя: ссылка }`) |
| `root` | `#title-view` — вся страница тайтла |
| `parts()` | части с сериями — свежий снимок: `[{ id, title, unit, count, watched, episodes: [{ n, title, image, watched }] }]` (`title` и `image` серии — из `data/episodes/<id>.json`, могут быть пустыми) |
| `progress()` | свежий прогресс (см. выше) |
| `canEdit()` | можно ли отмечать: подключён токен (или сайт открыт локально). Нет — показывать страницу без кнопок отметки |
| `canConnect()`, `connect()` | браузер ещё не подключён к отметкам (а сайт это умеет) — `connect()` открывает окно подключения прямо со страницы; после подключения страница собирается заново уже с кнопками |
| `setWatched(partId, n)` | «в этой части посмотрено n» (0…count); остановился на серии n → `setWatched(part.id, n)` |
| `markNext()` | +1: отметить следующую серию |
| `quiz` | опросник тайтла из `data/quiz/<id>.json` или `null` |
| `quizState()` | пройденный опросник: `{ answers, score, verdict }` или `null` |
| `scoreQuiz(answers)` | посчитать без сохранения: `{ score, answered, total, complete }` |
| `verdictFor(score)` | вердикт под оценку: `{ min, label, text }` или `null` |
| `saveQuiz(answers)` | сохранить ответы и оценку; возвращает оценку |
| `quizRun()` | готовое прохождение опросника: ход по вопросам и ответы-черновик, которые переживают закрытие окна и перезагрузку. `{ questions, i, question, last, answers, draft, answered(q), start(), pick(value), go(±1), canNext, canSubmit, firstUnanswered(), jump(n), submit() }`. `pick` возвращает `true`, если после ответа можно сразу идти дальше (вопрос с одним ответом, не последний); `submit()` сохраняет и возвращает `{ score, verdict }`. Теме остаётся разметка, клавиши и оглашение оценки — новые темы берут это, а не пишут ход опросника заново |
| `clearQuiz()` | снять оценку (пройти заново с чистого листа) |
| `onChange(fn)` | `fn()` после любой отметки — и своей, и пришедшей с другого устройства |
| `ident()` | сверка «то ли я включил» (`year`, `runtime`, `links`, `original` из `data/titles.json`): `{ original, year, length, facts, links }`. `facts` — готовые строки для показа (оригинальное название, год, длительность фильма или число серий), `links` — `[{ label, href }]` на карточку этой части в базах. **Показывать на каждой странице** тихой строкой в образе тайтла; ссылки — `target="_blank" rel="noopener noreferrer"`. Если число серий уже крупно стоит на странице — из `facts` его не повторять (взять `original` и `year`) |
| `chain()` | соседи тайтла по серии (`data/franchises.json`): `{ id, title, prev, next }` или `null`. Номера части и числа частей здесь нет нарочно: **место в серии («фильм 1 из 6», «сезон 2 из 3») не показывать нигде** — каждый тайтл сам по себе. `prev`/`next` — `{ title, href, added, released, status }`: `href` есть, только если часть уже добавлена на сайт; `released: false` — ещё не вышла. **Ссылка на следующую часть обязательна на каждой странице**: пользователь смотрит строго по порядку и переходит с части на часть. Нет `href` — показать название и «ещё не добавлен» / «ещё не вышел» |
| `neighbors` | соседние тайтлы в списке: `{ prev, next }`, каждый `{ id, title, href }` или `null` — для своей навигации |
| `art` | `hero(attrs)`, `logo(attrs)`, `cover(attrs)` — теги `<img>` арта с запасными адресами |
| `handoff` | `{ layers, data }`, если пришли с главной через `cover()`; иначе `null` |
| `assets` | `"themes/<id>/assets/"` |
| `reducedMotion`, `finePointer` | `prefers-reduced-motion` и наличие мыши (на телефоне hover нет) |
| `listen(target, type, fn, opts)` | addEventListener, который сам снимется при уходе со страницы |
| `loop(fn(now, dt))` | requestAnimationFrame-цикл, сам остановится |
| `layer(className, parent?)` | `<div>` (по умолчанию в `body`), сам удалится — для оверлеев, курсоров, фонов |
| `onCleanup(fn)` | любая своя уборка (таймеры и т.п.) |
| `esc`, `safeUrl`, `plural`, `unitWord(unit, n)`, `fmtScore(score)` | хелперы сайта |
| `fx` | `GameFX` — частицы (`fx.start({type, color, density})`) |

Пока модуль грузится, страница скрыта целиком (`.module-pending`), так что своя страница не мигает общей. Лайтбокс работает для любых `img[data-zoom]` внутри контейнера с `data-gallery`.

### Отметки

- Страница сама решает, **как** отмечать (клик по серии, рычаг, печать, перетаскивание закладки…), но правило одно: «остановился на серии n» = `ctx.setWatched(partId, n)`; повторный клик по последней отмеченной снимает её (`n − 1`). Кнопка «+1» — `ctx.markNext()`.
- Отметка сохраняется сразу (в браузере и, если подключён токен, в репозитории). После неё движок вызывает функции из `ctx.onChange` — в них перерисовать **только то, что зависит от прогресса** (серии, счётчик, доступность опросника), не всю страницу и не заставку.
- Те же функции вызываются, когда отметка пришла с другого устройства, — страница должна спокойно переживать любой новый прогресс в любой момент.
- Если `ctx.canEdit()` — `false`, кнопок отметки и опросника нет: страница только показывает прогресс и оценку. Но **молчать об этом нельзя**: владелец сайта на новом устройстве увидит страницу без кнопок и не поймёт почему (так и было с первым тайтлом). При `ctx.canConnect()` на месте главного действия должна стоять кнопка «подключить отметки» (`ctx.connect()`), а рядом — одна фраза, что сейчас только просмотр.

### Опросник

- `data/quiz/<id>.json` пишется под конкретный тайтл (см. `CLAUDE.md`); тема решает, как он выглядит и как его проходят: по одному вопросу, свитком, допросом, голосованием — в образе тайтла.
- Опросник открывается, когда `ctx.progress().status === "completed"`. До этого — видно, что он ждёт в конце, но пройти нельзя.
- Типы вопросов: `choice` (один ответ, по умолчанию), `multi` (несколько; пустой выбор — тоже ответ), `scale` (число от `min` до `max`). Веса ответов (`value`) **не показывать** — пользователь отвечает как есть, оценку видит только в конце.
- Ответы копить у себя, считать через `ctx.scoreQuiz(answers)` (`complete` — отвечено на всё), сохранять через `ctx.saveQuiz(answers)`. Оценка и вердикт — из `ctx.quizState()`; показывать её как итог в образе тайтла (приговор, печать, оценка в табеле…) с `ctx.fmtScore(score)`.
- Обязательно: «пройти заново» (ответы из `quizState().answers` подставляются), работа с клавиатуры и тапом.

## Заставка через переход: `cover()` + `ctx.handoff`

Чтобы вход с главной был бесшовным, заставка тайтла начинается ещё на главной:

```js
TitleThemes.register("<id>", {
  // по клику на баннер, на главной: закрыть экран своей заставкой (занавес, тучи, вуаль…), вернуть Promise,
  // который выполнится, когда экран закрыт полностью. Слои — только через t.layer().
  cover(t) { const c = t.layer("xx-curtain"); /* анимация закрытия */ return t.wait(600); },
  page(ctx) {
    // ctx.handoff = { layers, data } — если пришли с главной через cover(): слои уже закрывают экран,
    // нужно сыграть открытие и убрать их. ctx.handoff = null — страница открыта напрямую: обычная заставка.
  },
});
```

`t` (контекст `cover`): `item`, `progress`, `assets`, `esc`, `finePointer`, `data` (объект, который увидит `ctx.handoff.data`), `layer(className)` (элемент в `body`, переживает переход; на нём уже стоят переменные темы `--t-display`, `--t-accent`… — на главной их больше нигде нет), `wait(ms)`. Модуль на главной предзагружается при наведении на баннер. Пока идёт `cover()`, главная растворяется; страница тайтла собирается под закрытым экраном. Незабранные слои движок уберёт через 6 с. При `prefers-reduced-motion` `cover()` не вызывается.

## Что на странице тайтла

Страница — **только про то, где остановился, и про оценку после просмотра**: части и серии с отметками, прогресс, опросник и его итог, навигация к соседним тайтлам и назад к списку. Не показывать «о тайтле»: описание, жанры и теги, студию, год, рейтинги с сайтов, списки персонажей и сэйю, галереи. Не показывать даты (добавления, отметок). Статус словами («смотрю», «брошено», «в планах») на баннере и странице не писать — он виден по прогрессу и по категории в списке. Арт тайтла (постер, баннер, логотип, кадры серий) — только для оформления.

## Обязательные правила

- **Данные — только из `ctx`**: тема одна на тайтл, но число серий, частей и вопросов меняется (вышел новый сезон — добавилась часть). Ничего не захардкоживать (названия серий, количество, тексты вопросов) — модуль должен работать при любом числе частей и серий, с названиями и кадрами серий и без них, с опросником и без, при любом прогрессе и с `canEdit() === false`.
- Отмеченные серии — главное: они должны выглядеть пройденным путём; неотмеченные — понятно, но приглушённо; место, где остановился, видно сразу.
- **Всё через ctx** (`listen`, `loop`, `layer`, `onCleanup`, `onChange`) — после ухода со страницы не должно остаться слушателей, циклов и элементов.
- **Доступность и устройства**: отметка серий и опросник работают с клавиатуры и тапом (hover — только как дополнение); при `ctx.reducedMotion` — без анимаций и курсорных эффектов; на ширине 375 px нет горизонтального скролла, текст читается, по сериям можно попасть пальцем.
- **Производительность**: не больше одного своего rAF-цикла, анимировать `transform`/`opacity`, не вешать `box-shadow`/`filter` на сотни элементов. Но красота важнее — эффекты ради кадров не урезать.
- **Безопасность**: текст из данных вставлять только через `ctx.esc`, ссылки — через `ctx.safeUrl`.
- **Ассеты**: `python -P scripts/gen-image.py --manifest themes/<id>/assets.json` (ключ скрипт берёт из `~/.config/completionist-list/openai.key` вне репозитория); ключ никогда не печатать и не класть в репозиторий. Промпты — оригинальные элементы интерфейса «в духе» тайтла: орнаменты, рамки, разделители, фоны, текстуры, печати. **Без логотипов, без текста и без персонажей тайтла** (их арт берётся из официальных источников). Обычно 3–6 ассетов, каждый ≤ 300 КБ (`max_width`).
- Проверить в headless Chrome (`scripts/check-entrances.py`, `scripts/shots.mjs` — встроенный браузер со скрытой панелью замораживает анимации). Полный порядок работы и чек-лист — навык `.claude/skills/title-theme/SKILL.md`.
